# Correction to `K_dyn`: the greedy packing in PR #51 maximises the wrong thing

**Status:** correction to a merged result. `docs/topology_cycle_capacity.md` reports
`K_dyn(tau)` — how many reentrant loops a topology can hold simultaneously — and
flags it as *"a bound, not a measured count"*. That caveat matters more than it
looked. Every `K_dyn` value in that doc is a **loose lower bound**, low by 1.0× to
4.7× from a one-word bug, and by up to **7.5×** against an exact solve.

Experiment: [`experiments/topology_cycle_packing_exact.py`](../experiments/topology_cycle_packing_exact.py) ·
Archive: `result/topology/cycle_packing_exact.npz`

## 1. The bug

`pack_long_cycles()` in the merged experiment selects, at each greedy step,

```python
found = max(longer, key=len)      # longest cycle exceeding tau
```

The objective is to maximise **how many** edge-disjoint cycles fit. The longest
available cycle consumes the most edges per unit of count, so it is close to the
worst possible column for that objective. Changing `max` to `min` — shortest
cycle still exceeding `tau`, which is exactly the sustain gate's requirement and
nothing more — is the entire fix.

The bug does not affect the *shape* of the PR #51 result. `K` still falls with
`tau`, so the **capacity/duration tradeoff stands**. What changes is every
absolute number, and one qualitative claim: the ring is **not** the flat topology
that doc describes.

## 2. What the exact solve establishes

Three quantities per (topology, tau), all lower bounds on the true optimum
`K_opt`, plus an upper bound that can certify it:

| quantity | meaning |
| :--- | :--- |
| `merged` | `K_dyn` as committed in `cycle_capacity.npz` (greedy, `max`) |
| `greedy(min)` | same greedy, one-word fix |
| `ILP` | set-packing ILP (HiGHS) over simple cycles of length exactly `tau+1` |
| `UB` | `min(beta_1, floor(m/(tau+1)))` — edge budget and circuit rank |

`ILP == UB` **certifies** `K_opt` exactly. Every ILP packing is re-verified
independently before being reported: each selected cycle is confirmed to be a real
cycle of `G`, longer than `tau`, sharing no edge with any other.

**Headline.** On `ring(60, k=3)` at `tau=3` the true optimum is **45** edge-disjoint
4-cycles, using all 180 of 180 edges, with `UB = min(121, 45) = 45` attained — so
this is certified, not merely improved. The merged doc reports **6**.

The `tau=4..6` ring rows show the greedy fix alone changing nothing (6 either
way) while the ILP finds 36/30/25. That is the clearest evidence the greedy's
failure is structural rather than a tie-breaking accident: on a 6-regular
circulant, `cycle_basis` offers the greedy no short cycle to pick, and it stalls
at 6 regardless of the pick rule.

**Which method wins is topology-dependent, not density-dependent.** The ILP wins
on ring, smallworld (all four `tau`) and rgg (where solvable); `greedy(min)` wins
only on lattice2d — which is also the largest pool (258k length-6 cycles at
`tau=5`), so the ILP's disadvantage there tracks pool size and solve difficulty,
not graph density. Neither method dominates, so the table reports
`best known = max(merged, greedy_min, ILP)` rather than nominating a winner.

## 4. Caveats

- **Only the ring is certified** — 4 of 16 cells, all four ring rows. Elsewhere `best known` is a
  lower bound and the true `K_opt` lies somewhere in `[best known, UB]`. The
  remaining gap is real and unquantified: e.g. lattice2d at `tau=3` is bracketed
  only as `183 <= K_opt <= 216`.
- **The ILP pool is a heuristic restriction.** Optimising over cycles of length
  exactly `tau+1` is justified by an edge-budget argument, but edge-disjointness
  can force a packing through longer cycles where no length-`tau+1` cycle survives
  on the remaining edges. So a "pool-optimal" solve is not necessarily `K_opt`,
  and on lattice2d it undershoots the plain greedy.
- **Time limits are part of the result.** Rows marked `time-limit` report an
  incumbent, not an optimum. This is measurable: at a 60 s limit ring `tau=6`
  returns 24; at 120 s it certifies 25. The committed run uses 120 s.
- **`tau` is capped at 6.** Cycle enumeration is the binding cost, not the ILP:
  lattice2d has >258k length-6 cycles. Larger `tau` needs column generation with
  a resource-constrained shortest-path pricing subproblem rather than a
  pre-enumerated pool — the standard branch-and-price treatment of set packing.
- **This is structure, not dynamics.** `K` bounds how many loops the *graph*
  admits under the `tau < L` sustain gate. No dynamics are run here, and nothing
  claims a substrate can find, occupy, or use these packings — that remains the
  open question PR #51 also left open.
- **The `tau < L` gate itself is inherited**, including its boundary case
  (`tau = L` is marginally alive, per PR #54). Cycles of length exactly `tau+1`
  sit one step above that boundary.

## 5. What this changes downstream

`docs/topology_cycle_capacity.md` should be read as reporting a *lower bound with
a bug*, not a capacity. The specific claims to revisit:

1. **"the ring is flat"** — false. Ring capacity falls 45 → 36 → 30 → 25 over
   `tau=3..6`, a clean `~m/(tau+1)` edge-budget curve, all four certified.
2. **The 20–70× collapse from `beta_1` to `K_dyn`** — overstated. With corrected
   values, e.g. lattice2d `tau=3` is `721 -> 183` (3.9×), not `721 -> 39` (18×).
   The collapse is real but much smaller.
3. **Track C's prediction** that composites needing `k` simultaneous loops degrade
   as `k -> K_dyn` is unaffected in form, but the threshold `K_dyn` moves by up to
   7.5×, so any quantitative version of that prediction must be recomputed.
